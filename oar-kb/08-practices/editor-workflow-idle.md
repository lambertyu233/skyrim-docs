# 实战：靠编辑器做条件分流（高跟鞋 idle 为例）

> **素材来源**：巴哈姆特哈啦区教程《【問題】OAR的簡單應用 - 以高跟鞋閒置動畫為例》
> <https://forum.gamer.com.tw/Co.php?bsn=2526&sn=154942>
> 这是中文社区里质量最高的一篇 OAR 实操教程（截图全、步骤细），本页是它的结构化整理 + 与官方口径的对照。

## 课题

用户装了两套互斥的 idle：

- **A 组**：某女性 idle 动作包（会覆盖原版的站姿/坐姿 idle）
- **B 组**：三个高跟鞋 idle/行走动画（**DAR 格式**）

目标：**穿高跟鞋时用 B 组，穿一般鞋/赤脚时用 A 组**。

难点：两套都替换同一批角色动作，**默认互斥**，靠优先级只能二选一。

**解法思路**：用"是否拥有高跟鞋状态咒语"当条件开关——给 A 组的每个动作加上 `NOT HasSpell(高跟鞋咒语)`。

## 为什么这条路比 DAR 干净（作者的四条总结）

1. **所见即所得**：设定完马上看到动作生效。
2. **游戏内有即时 log**：能当场看到角色正在用哪个动作、动作目录、模组名、`.hkx` 档名。
3. **用 `.json` 管理使用者自订动作，不会污染原版 mod 的条件设定**——"光这点就比 DAR 改 txt 设定条件的方式干净进步很多"。
4. **完全兼容 DAR 的动作与条件**；DAR 的动作会被放到 **`Legacy`** 区，**以编号命名**。

## 完整步骤

### 1. 控制台选人

> 打开游戏，按 **`~`** 键打开控制台，**鼠标点选人物**，让游戏后台以玩家角色为目标。

⚠️ **这一步不能省**——后面所有实时状态显示都依赖它。

### 2. 打开 OAR 界面，切到 User 模式

> 再按 **`~`** 关闭控制台，按 **`Shift + O`** 打开 OAR 图形介面。
> 绿色部分是刚点选的人物名称；右边三个圆圈的 radio 选项是**检视模式 / 使用者模式 / 模组作者模式**。**请点选到使用者模式**。

选 **User** 而不是 **Author**，是因为不想改动原 mod 文件。

### 3. 浏览 replacer mod 列表

> Replacer Mode 页签一条一条的就是你曾装过的 OAR 动作模组……
> **如果是 DAR 的模组**，会统一放在最下面 **`Legacy`** 区域，展开就是动作编号。

> 补充（怎么找编号）：用 **MO2 打开该 DAR 模组的资料夹**就能找到编号——作者这次下载的高跟鞋 idle 编号是 **`68601`–`68606`**。

### 4. 打开 Animation Log

> 请点选右下方的 **Animation log** 按钮。
> 这时可以试试暂时先按 **Esc 关闭 OAR 介面动动你的人物**，只要控制台有正确选取人物，log 区块应该会即时告诉你**现在角色用的是哪些动作**（超级方便）。

### 5. 展开目标动作的 Conditions

> 再次打开 OAR 介面，使用 **User Mode** 找到你要更改的动作并展开。
> 以我为例，其中一个是 `Seamless Varied Feminine Idles OAR` 这个女性闲置动作包，可以看到它一共有 **8 个动作**。
> 这边先选第一个将它展开，并且找到 **Conditions** 这项也展开，代表这个动作会被触发的条件。

### 6. 加条件（关键操作）

> 为了新增判断 `HighHeelsConditionSpell` 是否存在，我们展开 conditions 项，按下 **Add new condition** 新增一个条件
> → 展开条件，可以看到有一大堆 DAR 条件的下拉式选单
> → 选择 **`HasSpell`**
> → **打勾 `Negate`**（把这条改成 NOT 逻辑，代表这条件**不成立**时才触发动作）
> → 这时可以发现条件显示变为 **`NOT HasSpell`**
> → 在 **plugin** 栏位输入该模组的 `.esp` 名称 `HighHeelsCondition.esp`，**FORM ID** 输入高跟鞋状态咒语的 ID：**`802`**

含义：以"该咒语不成立"作为触发依据。

### 7. 用图标实时验证

> 旁边的**绿勾**跟**红X** 代表角色当前状态是否符合触发条件。
> 像我现在有穿高跟鞋，所以（`NOT` 拥有 高跟鞋状态咒语）这条就是**红X**；等我脱掉高跟鞋它就变**绿勾**了，代表"没穿高跟鞋"这条件成立。

> 另外**黄方格**代表**随机机率条件**（想在随机轮播动画时用）。

**这是 OAR 最好用的自检开关**：脱一件装备、换一次状态，图标立刻变色。**调试时优先靠它，而不是靠反复重开游戏。**

> 小技巧：不知道咒语代码时，用控制台 `HELP` 指令等常规操作获取。

### 8. 保存（最容易忘的一步）

> 编辑完后，左上角动作名称会出现一个**橘色 `*`** 字号，代表你目前还没保存的客制设定；
> 而**黄色 `(User)`** 代表这个动作有在 User mode 被编辑过，若存档会建立干净的使用者自订设定档案。
> 按左下角 **Save user config** 保存，**橘色 `*` 消失**，代表这条动作条件修改成功。

> 照这个流程，把所有"穿高跟鞋时不想触发的 A 模组闲置动作"都一一加上条件并一一存档。

### 9. 回游戏验证

> 所有动作都改好之后，再穿上高跟鞋，就可以看到 B 组高跟鞋动画不会被 A 组覆盖了！
> 也可以用稍早介绍的 **log 功能**检查现在正在播放哪个动画，方便查错——**游戏内就可以做到这些**，非常方便。

## 作者的踩坑提示（原文归纳）

| 坑 | 说明 |
| --- | --- |
| **DAR 模组在 Legacy 里是编号，找不到** | 用 MO2 打开该 mod 的资料夹看编号 |
| **两套动作默认互斥** | 不管用 OAR 还是 DAR 装，它们都会替换同一个角色动作，**两者不能共存**——必须靠条件分流 |
| **不用条件咒语的话，DAR 路线极其麻烦** | 要一一改三个模组的 DAR 条件，或一一改装备关键字（xEdit） |
| **改了没保存 = 没改** | 看左上角有没有橘色 `*`，按 `Save user config` |
| **控制台没正确选人** | log 区块不会指向任何对象，调试失效 |
