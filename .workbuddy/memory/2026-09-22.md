## 踩到的坑（重要，已提炼进 MEMORY.md）

### 用正则改 frontmatter 时切错了边界，静默破坏 33 个条目

写了一个批量去除 `aliases` 中与 `tags` 重复项的脚本，用了这种写法：

```python
m = re.match(r"^---\r?\n(.*?)\r?\n---\r?\n", text, re.S)
raw = m.group(1)                      # 不含分隔符
new_text = text[:m.start()] + new_raw + text[m.start() + len(raw):]
```

**`m.start()` 指向 `---` 的起点（含分隔符），而 `m.group(1)` 不含分隔符** ——
两者混用导致开头 4 个字符的 `---\n` 被丢掉，同时原 `raw` 的末 4 个字符被挤到
`summary` 行末尾。

后果：构建从 43 条目跌到 **10 条目**（正好是我没改的那 10 个），
报「缺少 frontmatter」；而我第一版的修复校验脚本**只检查关键字段是否存在**，
所以误判成 `k=0` 就是干净的 —— 因为被追加的垃圾在**同一行末尾**，行首检查抓不到。

**正确做法**：拼回完整的 frontmatter 块，而不是对 group 的偏移做切片：

```python
body = text[m.end():]
new_text = "---\n" + new_raw + "\n---\n" + body
```

**校验也不能只查「字段存在」**，应做逐行断言「每个非空行都是合法的
`key: value`」，或用 `build_index` 的条目数做端到端校验。

> 教训与技能 `build-maintainable-kb` 里已写的「先逐文件断言锚点恰好命中 1 次、
> 再逐行比对证明只有目标行变化、字节增量等于替换差值」是同一条纪律 ——
> 我这次只在**锚点计数**上守住了，没有守**字节级等价**，于是坏在了切片上。

# 追加：索引页「侧栏收起」改为整条消失 + 左侧半圆悬浮按钮唤出

用户诉求（原话大意）：左侧筛选栏收起后**要完全消失**，另用一个**半圆悬浮按钮**来开启它。

### 改动实质

旧的收起是「把侧栏收窄到 78px」——`aside.collapsed{width:78px;flex:0 0 78px}` 外加四条
`aside.collapsed .sidehead…` 的窄栏适配规则，收起后仍留一条窄条。现全部删除，替换为：

- `aside.collapsed{display:none}` —— 侧栏整条让位，主区自动吃满宽度；
- 新增 `#navfab`（**放在 `</div>`(wrap) 之外的 body 层**，因为侧栏隐藏后按钮必须还在）：
  `.navfab{position:fixed;left:0;top:50%;transform:translateY(-50%);width:26px;height:58px;
  border-radius:0 30px 30px 0}` —— 贴视口左缘垂直居中的 **D 形半圆**，白底蓝字，
  hover 变实心蓝；`display:none`，只有 `.navfab.show` 才 `display:flex`；
- `aside.collapsed + main{padding-left:44px}` —— 用相邻兄弟选择器给正文让位，
  避免半圆按钮压住正文首列（`display:none` 不影响选择器匹配）；
- `#navtoggle`（侧栏内那个「‹ 收起」）**文案不再切换**：侧栏都隐藏了，它上面的文案没意义，
  收起态的唤出入口统一交给 `#navfab`；`aria-expanded` 两边同步更新。

### 一个容易踩的坑：DOM 桩把两段 JS 拼在同一个文件里跑

`check_index_ui.py` 是 `页面<script> + 断言段` 拼接后交给 node 执行的，
所以**同名顶层 `const` 会直接 `SyntaxError`**。绑 `#navfab` 时因此写成
`(function(){ const f=document.getElementById('navfab'); if(f) f.onclick=()=>setNavCollapsed(false); })();`
—— 用 IIFE 把变量关进局部作用域。这条已写进 SKILL.md。

### 顺手记一条环境坑

`grep -c $'\r' file` 在**本机 Git Bash 里恒等于文件行数**（256）—— 它并不真的在找 CR，
会把人误导成「文件有 256 个 CRLF」。判换行符一律用托管 Python 读**二进制**数 `b.count(b'\r')`。

# 追加：把「收起」按钮也换成同款半圆把手（样式统一）

用户追加要求：「把收起按钮也改成这样吧，保持统一」。

### 做法：一个 `.navfab` 外形，两个位置

- 删掉旧的 `.navtoggle` 小方框样式，两个按钮共用 `.navfab` 基类（26×58 右半圆、白底蓝字、
  hover 实心蓝、`position:fixed;top:50%` 垂直居中），只在 id 选择器里定位置与显隐：
  - `#navtoggle{left:230px;display:flex}` —— 展开态，`‹`，贴**侧栏右缘**（230px 正好是 aside 宽度）；
  - `#navfab{left:0;display:none}` + `.show{display:flex}` —— 收起态，`›`，贴**视口左缘**。
- `#navtoggle` 的 HTML 从「小方框 + `‹ 收起` 文字」改为 `<button class="navfab"><span>‹</span></button>`，
  仍写在 `<aside>` 的 `.sidehead` 里。

### 关键决策：`#navtoggle` 留在 `<aside>` 的 DOM 子树内，只用 `fixed` 挪位置

最初想把按钮移到 `</aside>` 之外（因为侧栏收起后把手不该还在），但那样有两个问题，
留在子树内一个都不用付：

1. **侧栏收起时自动隐藏** —— `aside{display:none}` 会让**整棵子树**不生成盒子，
   fixed 定位不会幸免（`fixed` 只改变包含块，不改变 `display:none` 的传播）。
   于是彻底不需要在 `setNavCollapsed()` 里额外 toggle 显隐类；
2. **`check_index_ui.py` 只静态解析 `<aside>` 内的 `<button>`** 来建 DOM 桩，
   移到外面就 `getElementById` 取到的是「按 id 预建的裸元素」（**没有 class**），
   于是「两个把手同 class」这类断言会假失败。

顺带：两个把手同用一个 `.navfab`，所以「统一」这件事变成了**结构保证**，
新增一条断言 `navtoggle.classList.contains("navfab")` 把这条设计固化成回归项。

### 校验（7 库全绿）

`validate_kb` ERRORS: 0 × 7；`check_index_ui` **24/24**（比上一步多 1 条统一性断言）× 7；

# 收尾：修掉那 3 个库的遗留（用户"你修了吧"）

## 过程中连续踩到两个坑，都靠"先干跑、再核验"兜住

### 坑 1：脚本**漏报**——只认不带前缀的写法

第一版 `linkify_refs.py` 的正则要求 token 首段是"真实库/分类目录名"，于是
`` `../02-face/racemenu.md` `` 这类**已带相对前缀**的引用（首段是 `..`）**全被跳过**。
实际待转数量：`character-appearance-kb` 真实 **34** 处，脚本只报 **2** 处（漏 32）。
→ 修：正则加一条 alternative 认 `(?:\.\./)+` 前缀分支，首段合法性改为校验**剥掉 `../` 之后**的首段。

### 坑 2：脚本**改坏内容**——把既有链接的 label 换成了嵌套坏链（严重）

库里存在这种作者风格 —— **label 用代码字体写的既有链接**：

```markdown
[`04-physics/physics-overview.md`](../04-physics/physics-overview.md)
```

旧脚本只按反引号匹配，把 **label 里**的路径也换掉了，产出：

```markdown
[[物理方案总览与选型](../04-physics/physics-overview.md)](../04-physics/physics-overview.md)
```

**最危险的是它四道校验全绿**：`validate_kb` 0 错误、`check_links` 全部有效（外层 href 是好的）、
`check_index_ui` 24/24、`build_index` 条目数 33/44/28 全对。损坏 33 行而**没有任何告警**。

- 发现方式：我给自己写的 **`verify_linkify.py`**（语义等价核验）报出 37 个文件异常、
  打印出「HEAD: `(../x.md)` vs 现在: `(../x.md)](../x.md)`」，一眼看出嵌套。
  → **只有"改前改后语义等价"这种证明式核验才能抓住它。**
- 处置：立即 `git checkout -- oar-kb character-appearance-kb behaviour-engine-kb` 整体回滚
  （工作树此前是干净的，HEAD = `0587773`，git 就是可靠备份），**零损失**。
- 修：与围栏同理，**再切一层段** —— 按既有链接 `\[[^\]]*\]\([^)]*\)` 切段，
  只对链接之外的片段替换；并加持断言 **`[` 与 `]` 各恰增加「替换数」**（可直接兜住误改 label）。
- 顺带确认 **`skyrim-tools-kb` 未受影响**：全库 grep 嵌套签名 `\]\([^)]*\)\]\(` 结果为 **0**
  （上一轮那些引用是我新写的，周围没有既有链接）。
