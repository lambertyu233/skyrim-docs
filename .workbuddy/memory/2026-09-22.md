## 踩到的坑（重要，已提炼进 MEMORY.md）

### 用正则改 frontmatter 时切错了边界，静默破坏 33 个条目

写了一个批量去除 `aliases` 中与 `tags` 重复项的脚本，用了这种写法：

```python
m = re.match(r"^---\r?\n(.*?)\r?\n---\r?\n", text, re.S)
raw = m.group(1)                      # 不含分隔符
new_text = text[:m.start()] + new_raw + text[m.start() + len(raw):]
```

**`m.start()` 指向 `---` 的起点（含分隔符），而 `m.group(1)` 不含分隔符** ——
两者混用导致开头 4 个字符的 `---\n` 被丢掉，同时原 `raw` 的末 4 个字符被挤到
`summary` 行末尾。

后果：构建从 43 条目跌到 **10 条目**（正好是我没改的那 10 个），
报「缺少 frontmatter」；而我第一版的修复校验脚本**只检查关键字段是否存在**，
所以误判成 `k=0` 就是干净的 —— 因为被追加的垃圾在**同一行末尾**，行首检查抓不到。

**正确做法**：拼回完整的 frontmatter 块，而不是对 group 的偏移做切片：

```python
body = text[m.end():]
new_text = "---\n" + new_raw + "\n---\n" + body
```

**校验也不能只查「字段存在」**，应做逐行断言「每个非空行都是合法的
`key: value`」，或用 `build_index` 的条目数做端到端校验。

> 教训与技能 `build-maintainable-kb` 里已写的「先逐文件断言锚点恰好命中 1 次、
> 再逐行比对证明只有目标行变化、字节增量等于替换差值」是同一条纪律 ——
> 我这次只在**锚点计数**上守住了，没有守**字节级等价**，于是坏在了切片上。

# 追加：把「运行时 morph vs 离线烘焙」补进 character-appearance-kb（v1.1.0）

用户给了一份 `D:\download\新建 文本文档.txt`，内容是问答：
「捏脸菜单里 CBBE 3BA 那一栏是哪个 mod / 怎么跟身型关联 / 为什么拖滑块衣服跟着变、
但 BodySlide 换身型就衣服不匹配 / 身型的原理是什么」。

### 核对结论：库里**只有碎片，没有主线**

已覆盖的碎片：`BODYTRI`、`Build Morphs`（`00-overview/morph-and-nif-basics.md`、
`03-body/bodyslide-outfit-studio.md`）、一句 conform（`06-troubleshooting/clipping.md`）、
一句 Zeroed Sliders（`05-distribution/obody-ng.md`）。

**缺的正好是那份问答的真正价值**：
1. 那一栏是**三层**叠出来的（RaceMenu 框架 / 身形的 `RaceMenuMorphs*.esp` / 你构建的 `.tri`）；
2. **运行时 morph（不改文件、只影响玩家）vs 离线烘焙（写进 .nif 顶点、影响所有 NPC）**
   这两条路径的对照 —— 这是"拖滑块安全、换预设穿模"的唯一解释；
3. conform 的实质 = 把身体 morph 数据复制到衣服顶点 ⇒ **衣服与身体拥有同一套 morph 名字**；
4. **Zeroed Sliders + Build Morphs + Batch Build** 这条正解工作流；
5. 两套预设体系（`.xml` 0~100 vs `.jslot` 浮点）**不通用**。

### 核实后新增/修正的东西（比原文更准）

- 用户的原文说「RaceMenu 滑块 -1~+1、BodySlide 0~100」。核实后：
  - **BodySlide 预设 XML 每个滑块存两个值**（体重 0 / 体重 100），NPC 按自身 weight **线性插值**；
  - **`.jslot` 的 `bodyMorphs` 存浮点**（实测样例 `0.50000`）；
  - 滑块上限由 `RaceMenuMorphs*.psc` 的 `OnSliderRequest` 里 `Float factor` 决定
    （社区记录默认 `2.0`，改它要重编译 `.pex`）→ **「-1~+1」这个说法不准确**，已列入纠错清单。
- 原文说「只对玩家和 **EFF 随从**直接生效」→ **EFF 那半句查无来源，未采纳**。
  可确认的只有「只影响玩家」；给单个 NPC 固定身材的真实途径是
  「本地构建专属裸体网格 → 复制到该 NPC 文件夹 → CK 建 ArmorAddon → 建 Armor → 设为该 NPC 的裸体皮肤」。
- 新增可复用事实：OBody NG 是**读取 `SliderPresets` 里的 `.xml`** 分配给 NPC，
  所以它**要求先做过一次 Zeroed Sliders + Build Morphs 的基础构建**；
  且 CBBE 3BA 的官方 Zeroed Sliders **带 100% 的滑块是正常设计，不要改**；
  必须勾 Group Filter 里的 `Unassigned` 组（很多服装在那儿）。
